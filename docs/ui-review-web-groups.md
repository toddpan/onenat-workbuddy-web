### ⛔ 新发现（定点复验运行时暴露的预存在缺陷）

### G-W-P0-3 空转折叠词表正则 \s 运行时丢失——空白分隔组合与英文多词 ACK 永不折叠（语义弱化）
- 截图：/tmp/uireview-shots/17/18（旧构建同象）、21/22（新构建："收到"+"好的"可折叠为对照；"收到，待命"以独立消息渲染未被折叠）
- 代码位置：web-ui.ts:17162–17164（GROUP_IDLE_ACK/STATUS/RE 构造）；正确先例：:17167 GROUP_NAME_ESC_RE（W3-3 拼接法，注释"三层转义已对齐"）
- 期望：spec §4.9【照抄】"含'收口'组合形态，正则语义不得弱化"；Android GroupRoom.kt:107 同构正则 \s 有效——"收到，待命"归一化（，→空格）后可折叠
- 实际（最新构建行为实测）：GROUP_IDLE_RE.test("收到，待命")=true（未归一化逗号形态恰可匹配），但 groupIsIdleRelayText("收到，待命")=**false**——normalize 将逗号压成空格后正则不识别空格：test("收到 待命")=**false**、test("got it")=**false**、test("待命")=true、test("收到")=true；GROUP_IDLE_RE.source 无任何反斜杠（"gots+it"、分隔类"[s，,、…]"）
- 根因：页面 JS 整体位于 TS 模板字面量内——源码 \\\\s 经模板转义产出页内 \\s，再被页内字符串字面量二次转义吃掉反斜杠 → new RegExp 收到裸 "s+"
- 影响面：混排（"收到，待命"）与英文多词（"got it"）空转消息**永不折叠**——恰为真实编排回复的最常见形态，折叠功能对主流场景失效
- 修法（一行级，照 :17167 先例）：分隔类与 ACK/STATUS 内 \\s 改字符串拼接规避双层转义（页内字符串须收到 "\\\\s"），或整式改由数组 join 构造；验收判据：修复后 groupIsIdleRelayText("收到，待命")===true 且 test("got it")===true
- 分级：⛔（spec 红线"不得弱化"；预存在非回归——首轮走查仅静态对照词表未运行时触发折叠，欠账在此销）
