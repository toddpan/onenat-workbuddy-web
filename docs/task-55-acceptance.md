## 实现位置与边界

- [workspace.ts](../src/workspace.ts)：稳定节点引用和节点侧词法路径规范化、绝对根目录校验、通用冲突与路径错误。
- [store.ts](../src/store.ts)：`getProjectsForWorkspace` 与 `upsertProject` 构成同步的查重和写入边界，涵盖已归档项目。加载旧库不去重，原身份不变的旧重复项目允许更新。
- [router.ts](../src/router.ts)：普通创建/编辑和导入共用上述约束；导入先寻找可见重复项，回调按发起人的当前账号及权限复用，不使用回调请求的 Cookie 改变归属。请求身份使用 `AsyncLocalStorage` 隔离。
- [server.ts](../src/server.ts)、[tool-ops.ts](../src/tool-ops.ts)、[mcp-server.ts](../src/mcp-server.ts)：HTTP/MCP 项目工具接收服务端已验证的用户身份，遵循项目权限并隐藏控制台回包中的 API key。请求体接收期间登出不会把用户降为空身份后误当服务通道。MCP 回放按身份分区；项目读请求重查权限，成功写入只在仍有权限时回放，兼顾重试幂等和权限撤销。

身份由文件归属 `dshRef` 和规范化根目录决定，项目默认执行节点不参与。mapping/app 使用稳定 ID；直连 URL 使用规范化 URL 本身。解析到的临时公网端口不参与 mapping/app 身份。

本版不自动识别符号链接、文件系统大小写折叠或不同引用其实指向同一物理目录；这些别名不自动合并。唯一性约束位于独立服务的单实例 store 内，不提供多个独立进程同时写同一个 JSON 文件时的分布式事务保证。

空根目录继续兼容未配置工作区的项目；已有相对路径可保留并修改其他元数据，新建或改绑必须使用节点侧绝对路径。AI APIKEY 沿用原有服务级权限；只有已验证的控制台用户身份执行用户级项目授权，工具参数不能伪造身份。

新增集成测试使用临时持久化目录、随机端口、两个本地测试用户和 mock DSH/ONENAT，经真实 HTTP 路由与 MCP JSON-RPC 调用验证。测试不会访问正式实例；模拟导入任务只调用本地 stub，没有真实模型派发或实际邀请邮件。

10 组覆盖：

1. 规范化新建、同节点冲突、跨节点区分及私有项目 404。
2. REST 三种编辑入口与 MCP 改绑失败无副作用、归档保留身份。
3. HTTP/MCP 用户权限、API key 脱敏、成员禁止管理、服务令牌冲突、写重试幂等、跨用户与权限撤销后的缓存隔离。
4. 导入预检查复用可见项目、隐藏冲突、旧重复项目可见项选择、非法路径/节点拒绝。
5. 导入回调与普通创建竞争、可见项目复用不覆盖、一次性回调与新导入归属。
6. 回调携带管理员 Cookie 不能越过发起人权限；管理员发起的导入按管理员权限判断。
7. 回调期间账号禁用和成员权限撤销生效。
8. 旧无 owner/仅有成员项目编辑不认领权限，旧重复项不删除或合并。
9. 慢请求与管理员请求交错不串身份；HTTP 工具接收请求体期间登出不升级权限；并发新建仅一个成功。
10. 服务重启后旧重复项、成员、凭证和任务项目引用保持，新重复绑定仍被拒绝。
